# IM Desktop Chat Implementation Plan

**Goal:** Match the user-provided desktop WeChat reference for text, image, file and group chat. User confirmed this scope; voice and calling are outside this iteration.

**Architecture:** Keep the existing collaboration services, encrypted transfer scheduler, authorization and durable outbox. Replace presentation in a scoped chat stylesheet and connect prepared attachments to the existing composer send action. File selection is preparation; sending authorizes automatic upload and delivery. Keep recovery errors visible and preserve keyboard and account/conversation fences.

**Tech Stack:** Electron, browser DOM modules, existing CSS/i18n, Node and Electron tests.

- [x] Add a real DOM regression test for prepared file -> composer send -> one sendAttachments call; no manual upload and no duplicate confirmation. Check double-send, failure retention, conversation/policy fences and ordinary text fallback.
- [x] Add composer attachment hooks in `collaboration-composer.js`, wire them through `collaboration-center.js`, expose prepared state/submission from `collaboration-attachments.js`. Keep reply/@/edit submissions on their existing text path so metadata is never silently discarded.
- [x] Move transfer cards into the input surface; use compact file icon, filename, human-readable size, remove action and honest progress/recovery states. Hide completed history from the draft surface without removing recoverability.
- [x] Add scoped `collaboration-desktop.css`: 64px navigation + 280px list, no standalone banner, flat surfaces, rectangular active row, 40px avatars on both sides, green own bubbles, neutral time dividers, roomy input and quiet toolbar. Preserve small panel layout and light theme.
- [x] Improve message attachment cards with readable file type, image preview presentation, no raw MIME strings; keep signed authorized downloads.
- [x] Run targeted composer, transfer, timeline, group and UI tests. Render real app markup with fixture messages in Electron at desktop and narrow sizes, inspect screenshots and fix overflow/contrast before completion.

No live messages to user contacts or production server changes are required for this client redesign. Preserve unrelated working-tree changes. Full two-account production IM acceptance remains distinct from fixture-based UI and storage verification.

## Drag/drop and screenshot paste follow-up

- Explicit preload drop bridge resolves native `File` objects with Electron `webUtils`; fabricated renderer path objects cannot use this bridge. Existing ID-only transfer commands remain unchanged. The new import command validates the conversation and a bounded local source before calling the existing encrypted prepare path.
- Paste reads image bytes only on a paste gesture. PNG/JPEG/WebP are recognized by signature in main; pasted images are limited to 20 MiB. Ordinary text paste remains native. Each message holds at most 20 prepared attachments; directories and symlink sources are rejected.
- No upload or message send occurs on drop/paste. Files enter the current conversation's draft area and reuse explicit composer send, durable attachment intents and Qiniu encryption/upload.
- Temporary clipboard files are mode 0600 in an app-owned directory and removed after encryption or failure. Current account/conversation/policy checks fence late results.
- Verification: new import-source tests, real encrypted transfer-runtime import test, preload/native-file boundary test and Electron DOM drop/paste test passed. Existing attachment-send, transfer IPC, composer-attachments, attachment UI and locale checks passed. Main/preload syntax and whitespace checks passed.
- No installer was built or published. Because preload/main IPC changed, an already-running development client must be fully restarted; a packaged client requires a new build.
