# Auto / 手动选模闭环实施

依据：`2026-08-29-auto-model-re-audit.md` 的 13 项已确认问题。

## 不变量

- 默认模型只是指针，不能改变模型身份。旧选择仅在身份可证明时迁移。
- 目录失效先进行有界、去重刷新；明确撤销不得回退到旧连接。
- 插话、草稿、恢复和用量均归属原会话/任务，不随当前界面改变。
- 引擎回收同时考虑界面引用与真实未完成工作；模型切换不丢历史。
- 推荐 Auto 在真正缺失目录时保留既有强默认；手动和自选池不扩大。

## 验证边界

先将审查中的受控复现改为预期正确行为的回归，并确认原代码失败。
完成各域测试后跑完整套件。离线替身不代表真实供应商付费调用或发布安装包
已验收；不在本次自动提交、推送或部署。

## 已验证的身份与恢复

托管 preset ID 始终包含模型名 SHA-256 的 128 位摘要，默认模型独立指定。
客户端连接 ID 同时绑定 preset、协议、供应商标识与 endpoint，不绑定令牌，
所以令牌轮换不改变任务身份，真正换连接仍会被恢复校验阻止。

刷新签名配置之前保留旧目录的身份映射，缓存重载后仍可将旧裸 ID 迁移至
原模型；冲突或无法证明的映射不猜测。旧选择的模型下架时明确失败。
新回执标记 identityVersion=2，模型和连接都必须一致。旧回执只接受可核实
的历史连接形式，不能放宽成任意同名模型。

目录区分 ready/stale/unavailable；stale 在执行准入前通过既有去重刷新器
刷新一次，取消仍优先；ready 中没有授权模型时不回退。后台 job 唤醒先校验
job/wake 的任务、会话、工作区、所有者，再传递 sourceTurnId。

对应回归：`test-model-catalog-lifecycle.mjs`、`test-model-identity-migration.mjs`、
`test-long-task-session-wakeup.mjs`；既有选模、执行和服务端配置回归仍通过。

## 异步操作归属

插话在附件预处理之前捕获 turn/generation/runner/attempt/owner，异步返回后
重新校验；失效插话不写入新任务证据、不注入新任务。未接收的输入保留原有排队
语义，已被旧执行器接收的输入不重复发送。

`composer-drafts.js` 统一保存每个会话的文本、附件和角色创作标记。发送失败只
恢复它自己清空且尚未被编辑的草稿；切换会话会恢复可见附件，不覆盖其他会话或
用户的新输入。选模快照读取失败统一交回主进程持久化偏好判断，仍等待该会话尚未
完成的选择保存，不以过期的前端缓存擅自换模型。

对应回归：`test-model-ownership-steer.mjs`、`test-model-ownership-composer.mjs`、
`test-model-picker-state.mjs`，以及真实 Electron 的 `test-renderer-import.cjs`。

## 引擎与用量所有权

共享引擎分别记录界面引用和真实工作租约。压缩的原始 SDK Promise、原生子任务
与会话活动未结束时，旧配置仍可存活；HTTP 等待超时不等于引擎完成。明确取消、
实际完成、进程退出会释放对应租约，硬退出主动拒绝悬挂请求并清理旧视图。

共享配置只排除会话级 `CLAUDE_CONFIG_DIR`，不忽略密钥、代理、TLS 或权限差异。
被同步 invalidated 的 runner 不再启动；原有 resume ID 恢复链保持不变。
非当前连接的环境合并清除全局 OpenCode 模型、地址、密钥和协议覆盖，保留图片
识别等共享能力，避免选了 B 实际请求 A。

用量在事件传输层按执行身份核算，而不依赖聊天气泡是否活动。只接受有实际
assistant 模型元数据的 canonical step-finish，按 part 增量去重；子会话、
空闲压缩、主轮均进入 provider/model 分桶，重复 SSE 和同库恢复不会重复累计。
去重回执为应用生命周期内的内存状态，不包含原始对话；不宣称跨应用重启 exactly-once。

`test-opencode-runtime-ownership.mjs` 覆盖真实 host 调用链的可控竞态。
`test-opencode-bundled-usage.mjs` 启动本机打包引擎与隔离的模型 HTTP 替身，检查
真实子任务、压缩、SSE 格式和重放去重，不调用付费模型；没有当前平台引擎时明确跳过。

## 用量数据库与滚动升级

记录与重试携带 providerID 和固定 reportId，本地持久化保留分桶和去重标识。
服务端在同一事务内写收据、既有总量和新增供应商明细。迁移
`031_usage_provider_identity.sql` 仅新增表和视图，不修改旧 `usage_daily` 唯一键，
因此旧服务器仍可按原 conflict target 写入。历史与旧服务器增量归入 unknown，
原有总量接口不变，新增 byModel 返回供应商细分。

真实临时 PostgreSQL 回归 14/14 通过，包含旧二进制 upsert、新旧并存、重复并发
请求、签名校验及任一计数写入失败时事务回滚。临时数据库已删除。

## 尚未覆盖的发布边界

- 打包引擎的标题生成直接调用模型，不产生可归属的 step-finish 用量事件。
  主轮、子代理、压缩已纳入；不能宣称所有辅助调用都已纳入客户端统计。
- 客户端上传重试队列仍在内存中；应用崩溃后的待上传持久恢复不是本轮保证。
  旧服务器不保存 reportId，跨新旧服务器的同一重试也无法追溯去重。
- 去重回执随本次应用生命周期增长；当前不贸然淘汰，以免历史 SSE 重放重复计数。
- 不把离线模型替身等同于真实供应商质量、实际账单、多轮网络故障或客户安装包验收。
- 发布需先应用服务端迁移再更新服务端，并发布客户端；主进程修改需要完整重启。
  本轮未提交、推送、打包或部署，不宣称线上客户已收到修复。
