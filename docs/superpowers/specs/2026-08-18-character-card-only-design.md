# 角色卡唯一模式设计

## 目标

Lily Workbench 只保留角色卡作为对话角色能力的用户入口。独立人物设定、任务设定和世界书全部停用，避免用户需要理解多个相互叠加的上下文系统。

## 用户可见行为

- 角色管理页只展示角色卡列表、详情、导入、编辑、复制、归档和当前对话使用。
- 不再展示人物设定、世界书相关标签、创建、编辑、导入、预览、激活和删除入口。
- 会话角色状态只显示当前角色卡，不显示人物设定或世界书状态。
- 角色卡导入数据中的 `character_book` 不进入运行时上下文，也不提供单独管理入口。

## 运行时边界

- 新会话和已有会话只允许使用 `characterRevisionId`。
- `personaRevisionId` 和 `worldBookBindings` 即使存在于旧数据库、旧绑定、恢复快照或导入包中，也必须在会话 admission 和每轮 prompt 编译前被忽略。
- 角色卡运行时只使用角色卡自身的受支持字段：身份、描述、性格、场景、示例对话、系统提示和历史后置指令；其中系统/历史指令继续遵守现有低权限与安全边界。
- 角色卡内嵌世界书不执行、不扫描、不创建 checkpoint。
- 新的绑定写入路径拒绝人物设定和世界书字段，返回稳定的“功能已停用”错误；回退到原声 Lily 仍然可用。

## 数据兼容

- 不删除旧表、旧 revision、旧资源或旧会话事件，避免破坏历史会话、导出包和数据库升级。
- 旧绑定保持可读，但投影为角色卡唯一有效配置；旧的人物设定和世界书仅作为惰性历史数据存在，不会被读取到 prompt。
- 旧导入包可以继续被识别，但导入时只落角色卡；其中独立人物设定、世界书和内嵌 `character_book` 被忽略并写入非阻断诊断。

## 实现边界

1. 在 main admission、snapshot、turn compiler 和 prompt builder 形成单一过滤边界，确保任何旧路径都不能注入已停用上下文。
2. 在 IPC/preload 保留必要的旧通道兼容，但新的人物设定/世界书写入返回 `FEATURE_DISABLED`；读取可以继续返回空集合或兼容错误，不泄露旧内容到 renderer。
3. 在 renderer 只保留 `characters` tab 和角色卡操作，删除相关状态、徽标、预览及入口。
4. 保留角色卡现有选择、激活、revision pin、历史和更新提示行为。

## 验收标准

- 角色卡选择后，角色身份和角色卡内容仍能进入每轮请求，并通过现有 application trace 反馈应用状态。
- 含旧 `personaRevisionId`、独立 `worldBookBindings` 或内嵌 `character_book` 的会话，实际请求中均不包含这些内容。
- 新 UI 不出现人物设定、任务设定或世界书入口、标签和状态。
- 原声 Lily、角色卡切换、旧会话恢复、导入和导出不因停用功能而崩溃。
- 新增回归测试覆盖运行时过滤、IPC 禁写、旧绑定兼容和 renderer 单标签模式。

## 非目标

- 不删除角色卡本身的性格、场景、示例对话或系统提示字段。
- 不重做角色卡编辑器视觉样式。
- 不迁移或清理历史数据库中的人物设定和世界书内容。
