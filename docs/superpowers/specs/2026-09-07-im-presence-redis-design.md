# IM 在线状态与 Redis 设计

用户已批准：PostgreSQL 保留可靠消息与游标；Redis 共享在线状态、通知和相关限流；好友、Team、私聊显示统一，故障不拖垮聊天。当前工作区包含尚未提交的远程任务实现，继续原位增量开发，禁止搬走或覆盖已有工作。

## 状态契约

仅 online/offline/unknown。online 表示至少一个当前有效账号会话的设备有未过期连接；不是正在阅读、活跃操作或任务可立即完成。连接 30 秒续租，75 秒有效；用户关闭连接只删除该连接，旧连接不能删除新连接。离线无最后上线时间。客户端数据过期、网络错误、Redis 不可达统一 unknown；不能把未知画成灰色离线断言。

按环境前缀隔离 Redis key/channel。连接租约使用服务端时间、唯一连接 ID、user/device 绑定及 TTL；多设备汇总限制在有效 user_sessions/user_devices 内。读取必须批量，不能每个成员各发一次 Redis 请求。断线清理最佳努力，进程崩溃由 TTL 收敛。Redis 恢复后活连接心跳重建租约；删除不复活连接，乱序旧通知只能触发重新读取。

## 权限与接口

新增签名 POST /api/collaboration/v1/presence，body={deviceId,userIds}，userIds 去重后不超过 200。复用正式账号/设备/IM gate。返回 {ok:true,states:[{userId,presence,onlineUntil}],observedAt}；不返回设备 ID 或会话 token。只查询自己、未拉黑的有效好友、共同有效 Team 成员；账户停用、会话撤销、移出组织后不能透过缓存继续看到在线状态。无权对象不透露是否存在，返回 unknown。权限依据 PostgreSQL，不使用 Redis 授权。

企业目录复用同一在线查询层；无 Redis 配置可保持开发单实例模式，生产配置了 Redis 后发生故障必须 unknown，不能偷偷退回本机 Map 当成全局事实。

## 推送与可靠性

现有消息 outbox + PostgreSQL LISTEN/NOTIFY 保持不变。Redis Pub/Sub 只广播临时变更提示，不是消息存储；提示不携带在线事实或敏感资料。客户端按授权目标批量刷新，合并高频提示；断线重连和定时刷新补偿漏通知。没有订阅时不广播任何用户列表。跨实例 typing 可沿 Redis 转发，但不得绕过已有会话授权，不能重复本机回显。

## 客户端与 UI

主进程维护账户隔离、短期内存快照，不写持久联系人状态。监听提示失效缓存；刷新串行/合并、超时有界；切换账户、撤权、离线立刻失效。不能把 presence 查询放进现有会话切换关键路径。好友行、Team 成员、私聊标题复用一个展示函数：绿点+在线，离线为低强调文字，未知为状态暂不可用；无红色警报、不增加面板。过期定时重绘只改状态节点，不替换输入框、草稿、成员选项或滚动位置。三语言与浅深色、窄屏兼容。

## 运行与验收

Redis 私网/loopback，认证、禁用公网暴露、内存上限、无消息正文、连接与命令超时、关闭离线命令无限排队。启动失败不阻断 API；降级日志不含 URL 密码。健康信息区分核心 API 与临时状态依赖，Redis 故障不能令消息 API 的 liveness 失败。

验收：真实 Redis 的跨实例连接聚合、旧断线/重连、TTL、撤销设备、Redis 重启与恢复、权限过滤；真实 Electron 好友/私聊/Team 状态一致、未知降级、迟到响应与草稿保留；生产部署只在本地回归和独立审查通过之后。物理设备/平台未执行项单独记录，不把 fixture 等同实机。
