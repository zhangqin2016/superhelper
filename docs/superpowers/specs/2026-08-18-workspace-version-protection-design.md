# 工作区版本保护设计

## 目标

让普通用户在不理解 Git 的情况下获得可解释、可恢复的工作区历史：Lily 在任务完成后自动保存安全版本，用户可以查看历史、手动保存当前状态，并在恢复前看到影响范围。

## 产品原则

- 用户看到“版本保护”，不需要看到 Git、分支、暂存区或命令行。
- 不初始化、修改或提交用户已有的 `.git`；Lily 使用工作区内 `.lily-work/version-vault.git` 作为隐藏版本库。
- Git 只是版本引擎，不是备份。默认不联网、不 push、不上传内容。
- 任务级回退、运行时检查点和工作区版本保护各司其职，不互相替代。
- 自动保存只在任务开始时工作区没有未保护修改时执行；存在用户预先修改时，自动保存暂停并明确提示，避免把不相干内容混入版本。
- 恢复前创建安全快照；恢复只允许白名单路径，拒绝 `.lily-work`、符号链接和超大文件，不使用 `reset --hard`。
- 提交说明只使用固定的 Lily 文案，不写入用户原始提示词、路径中的敏感内容或工具输出。

## 数据模型

`WorkspaceVersionService` 对外提供：

- `status(workspacePath)`：引擎、首个版本、未保护修改、受保护文件数量。
- `history(workspacePath)`：固定数量的版本摘要。
- `save(workspacePath, reason)`：显式保存当前安全文件。
- `autoSaveTurn({ workspacePath, baseline, changedPaths, terminal })`：仅在基线干净且任务成功时保存本次变更。
- `restore(workspacePath, revision)`：先保存恢复点，再恢复指定版本，并返回受影响文件数。

版本库使用 bare Git + 独立 `GIT_INDEX_FILE`，因此不会生成工作区根目录 `.git`，也不会污染用户自己的 Git 索引。忽略策略同时过滤依赖、构建物、缓存、密钥和 Lily 内部目录；单文件和总大小均有上限。

## 降级

启动或首次打开版本保护时，服务优先解析已安装的 `git` runtime pack；缺失时通过现有依赖下载器按需下载、校验并准备，不要求客户安装 Git。Git 依赖安装失败或 vault 损坏时，服务才切换到 `.lily-work/version-snapshots` 的本地快照存储。快照只保留同一安全策略允许的普通文件，恢复仍先生成恢复点。UI 继续显示“本地保护”，不把降级伪装成 Git。

## IPC 与 UI

项目菜单新增“版本保护”，打开一个轻量面板：状态摘要、未保护修改提示、最近版本、保存当前版本、恢复按钮。恢复必须二次确认，确认文案包含版本时间和文件数量。失败时保留当前文件和错误信息，不自动删除用户内容。

## 验收标准

1. 新工作区首次打开不会修改用户 `.git`，也不会把 `.lily-work` 纳入版本。
2. 自动保存只保存成功任务的变化；预先存在修改时不自动混入。
3. 显式保存和恢复可覆盖新增、修改、删除文件，且恢复前有恢复点。
4. 密钥、依赖、构建物、符号链接和超大文件不会进入版本。
5. Git 不可用时核心保存、历史和恢复仍可工作。
6. 主进程异常不会让版本保护阻塞任务归档或主流程。
