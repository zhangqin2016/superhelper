# Lily Workbench 行业精选目录设计

## 目标

把官方角色库从当前的高频办公与生活精选扩展为可长期维护的行业入口，覆盖主要工作与生活场景。用户可以在角色库中按行业找到可直接使用的角色、设定和世界书，而不是自己理解抽象字段后从零配置。

本次目标规模：约 60 个官方角色、约 20 套官方世界书；现有 22 个角色、7 个设定和 7 套世界书继续保留并纳入统一目录。

## 内容范围

角色覆盖以下行业与横向能力：

- 企业管理、产品、项目、行政与人力资源
- 技术研发、数据与 AI、信息安全、IT 运维
- 设计、建筑与工程
- 教育、培训与研究
- 医疗健康与心理支持
- 法律、合规、金融、会计与保险
- 地产、制造、供应链、物流与采购
- 零售、电商、市场、销售与客户服务
- 媒体、内容、翻译、广告与公关
- 餐饮、旅游、酒店、活动与社区服务
- 公共服务、非营利组织、农业和自由职业

每个角色必须提供：适用场景、所需输入、标准工作流、交付物、质量检查、边界、标签和中英文内容。高风险角色必须说明不替代执业人员、不编造事实、不保证结果，以及何时需要线下升级。

设定保持跨行业、面向用户工作方式的定位，例如项目负责人、学习者、创作者、职业转型者和生活管理者；不把行业角色重复复制成设定。

世界书分为行业规则包和通用工作包。每套世界书包含 3 至 5 个可独立触发的条目，至少有一条常驻规则，并提供主关键词、次关键词、插入位置、扫描深度、token 预算和递归限制。内容聚焦回答行为，而不是行业百科：术语、流程、证据、交付标准、风险和升级条件。

## 质量标准

1. 角色不能只改名称。每个角色必须有该行业特有的输入、决策流程、交付物和验收标准。
2. 世界书不能只提供背景介绍。每个条目必须能改变回答的取证、流程、结构、语气或风险处理方式。
3. 医疗、法律、金融、保险、公共安全和心理支持内容必须有明确边界，不能伪装成诊断、法律意见、投资承诺或危机处置。
4. 中英文版本保持同一语义和边界；缺少行业事实时要求用户补充资料或标注不确定性。
5. 官方安装必须保留 trusted provenance，重复安装幂等，升级通过官方版本号识别；安装后可继续编辑为用户自己的修订版。

## 实现边界

- 在现有官方目录协议、IPC、preload 和角色库 UI 上扩展，不新增第二套安装或绑定机制。
- 角色目录拆分为基础目录和行业目录，避免继续扩大单一文件的维护负担；对外仍由现有 `listOfficialCharacters`、`getOfficialCharacter` 等 API 返回统一列表。
- 世界书继续复用现有 canonical entry 和 scan policy 模型；新增分类必须同步角色库排序和中英文阿拉伯文分类翻译。
- 现有用户创建的角色、设定、世界书和未提交修改不迁移、不覆盖。

## 验证

- 目录测试验证总数、唯一 ID、分类、字段完整性、双语内容和高风险边界。
- IPC 测试验证行业官方内容仍经过可信来源安装、幂等安装和 owner 派生。
- 角色库模型和本地化测试验证新增行业分类可显示、筛选和排序。
- `git diff --check`、Node 语法检查和现有角色世界测试必须通过。
