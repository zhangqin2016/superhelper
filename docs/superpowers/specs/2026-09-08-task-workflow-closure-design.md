# Lily 任务流程闭环修复设计

日期：2026-09-08

状态：待用户审核；不是实现完成记录。

审计基线：`87056699`。范围是本次任务流程审计发现的跨轮需求、任务类型、验收、重复输出和恢复断点。已有测试通过不作为新场景的验收证据。

## 1. 产品目标和边界

让同一份最新、经用户授权的任务要求贯穿接收、执行、后台等待、恢复、验收和交付。用户可以自然语言继续、补充、撤销要求；平台不能因为摘要、队列或恢复路径而漏项、恢复已撤销要求、重复执行未知结果的写操作。

“闭环”必须区分三层：

1. 实现闭环：生产入口确实使用修复，不是孤立函数或提示词。
2. 验证闭环：故障复现、修复后回归、跨模块和客户端场景验证。
3. 交付闭环：源码、实际运行版本、测试证据及剩余限制可追溯；未经安装版验证不得声称安装版问题已解决。

本轮不发布服务或安装包、不推送远端、不操作客户工作区。只使用合成测试工作区。真实模型验证使用用户已配置且授权的模型路径，不读取或输出密钥，不在缺失配置时擅自换供应商。

不增加工作流面板，不复制 OpenCode 模型循环和原始历史，不改变已选模型、工具和权限模式。不用固定短超时截断健康长任务。

## 2. 方案选择

### A. 统一现有任务合同、证据和恢复入口（采用）

复用 TaskCore、持久化 admission、回执、已有队列和 finalizer。增加必要的小型领域模块，使跨轮引用、当前需求版本和恢复身份明确。优点是修复实际断点、保留已有强默认行为；代价是需要跨入口集成测试和兼容读取。

### B. 仅修类型字符串和增加关键词（不作为完整方案）

能快速修复个别复现，但不能解决长要求、范围撤销、未知验收和恢复一致性。只把确定的字面匹配修复作为 A 的局部步骤。

### C. 另建完整 DAG 执行引擎（本轮不采用）

会新增第二套执行权威，放大权限、取消、重播和历史一致性风险。当前子任务图是观测投影，必须如实保持这一含义；不能将其标为已实现平台依赖调度。

## 3. 子项目 A：任务身份、完整需求与用户修订

### 3.1 权威来源

完整用户输入留在已有 durable admission，不将 1,000 字摘要作为唯一原始要求。TaskCore 以 owner/session/project/sourceTurnId 绑定可读取的权威输入和合同版本；恢复和继续读取相同引用。

新增字段必须是版本化、可选、向后兼容的元数据。摘要继续有界，不能把所有历史全文反复注入每次模型请求。超长原文通过已有分段/文件读取机制取用；截断必须显式标为未完整检查，不能判断全部覆盖。

需求记录具有稳定 ID、来源轮次、原文证据、状态和修订号。状态区分 active、satisfied、withdrawn、superseded；历史不删除。模型提出的计划与完成状态不能替代用户需求。

### 3.2 继续与新任务

明确的“继续”及常见礼貌前缀可走低成本确定性路径。其他续接语义使用现有选定模型的合同提案接口表达，主进程检查作用域、当前轮次和源合同版本，不能让模型选择任意历史任务。

不把所有短消息默认解释成继续：显式新任务、无有效旧任务、跨账号/跨会话以及已经离开的旧任务必须保留当前新任务路径。解释不明确时保留原文及历史上下文，不恢复旧任务的执行权限，不额外执行工具。

### 3.3 范围缩减

模型不能自行删要求，但用户可以。用户修订应携带指向本轮真实输入的证据，并与被撤销需求或精确文件身份绑定。确定的文件撤销可以机械核对；有歧义的撤销不能从宽泛词语推断为删除全部要求。

当前有效验收集合由最新需求版本生成，不再无条件 union 所有历史 deliverables。撤销意味着不再要求交付，不意味着删除磁盘上的现有文件。正在执行的已授权外部操作不能被悄悄倒转；结果保留并标明不再属于当前交付范围。

### 3.4 主要接入点

`src/main/intent-contract.js`、`task-contract.js`、`task-core-contracts.js`、`task-core-runtime.js`、`turn-intelligence.js`、`task-original-acceptance.js`、`model-turn-contract-refinement.js` 及现有 store 接口。

抽取需求来源/修订逻辑到职责单一模块，避免扩大已有协调器。旧记录缺乏完整来源时保留可用结果并标明验收范围未知，不伪造完整需求。

## 4. 子项目 B：统一执行类型和验收

### 4.1 类型能力统一

以 `task-type-schema.js` 的规范类型为唯一来源，提供执行/创作/只读能力判断。文档创建与媒体生成必须进入原始需求验收；读取文档、普通问答不能因此被当作需要创建产物的任务。

保留现有文件存在、非空、结构、渲染和真实工具回执检查。通用原始需求覆盖是补充，不能放宽专项标准。

### 4.2 证据与覆盖

验收按有效需求 ID 逐项绑定完成后的工具证据、产物身份和版本。代码负责真实回执、成功退出、文件指纹、时序和身份；模型只判断证据是否满足语义。

不能只相信模型的 `exhaustive:true`：主进程必须核对所有当前有效需求 ID 恰好被覆盖一次。需求提取本身的完整性若未证实，整体不得升级为全部验证完成。

使用需求相关证据窗口，保留可追溯证据引用；旧证据不能因为只取最近 32 个工具而被默认为不存在。读取和模型输入仍有预算；超过预算保留 unknown，并说明覆盖范围，不无限增加模型调用。

### 4.3 unknown、missing 与交付

- missing：存在明确、当前有效且未完成的要求，沿用有界补做路径。
- unknown：保留已生成内容和产物，不升级为 verified_complete；只在存在明确、可执行且授权的验证动作时发起一次针对性补验。
- 不可用验收服务：不得无限重试、重做原任务或阻止普通回答交付。
- completed：只表示执行轮次结束，不能自动表示全部用户要求已验收。

最终面向用户的完成摘要、任务状态和归档使用同一验收结果。允许保留原始回答，但必须有紧邻交付的一句具体未验证说明，不能用整页警告或空回答替换成果。只对实际参与验收的执行任务使用该说明，普通问答保持不变。

这一边界遵循项目既有 fail-open 交付政策：不会因语义检查失败而清空有用回答；也不会将未确认的完成断言当作平台认证。

### 4.4 主要接入点

`parent-task-closure.js`、`task-type-schema.js`、`task-original-acceptance.js`、`turn-acceptance-recovery.js`、`task-result-runtime.js`、`task-run-state.js`、`turn-terminal-finalizer.js` 与现有结果展示/i18n。

## 5. 子项目 C：恢复和后台唤醒一致性

### 5.1 租约到期重试

启动扫描区分可领取任务和尚未过期的领取记录。为最早的未来租约安排一次可取消的到期扫描；处理后重新计算下一次唤醒，不高频轮询、不占住事件循环。

每次扫描重新校验账号、会话存在性、权限和任务终态；关闭服务时清理定时器，迟到回调不能重启已关闭的服务。休眠唤醒后根据当前时间重算，不依赖定时器准点触发。

仍使用现有 SQLite CAS、claim token 和稳定 recoveryTurnId。已存在 admission 的续跑只对账，不再发送一次。结果未知的外部操作保留核验/人工确认边界，不以恢复为名自动重放。

### 5.2 同一来源解析器

普通源轮次继续、父任务补做、后台作业唤醒、队列重启均通过相同的作用域校验和源合同读取。不能只在重启路径恢复 sourceTaskCore。

源记录缺失时保留后台作业实际结果，明确无法完整核验原任务；不猜测另一条任务作为来源，不扩大下载、文件或工具授权。

### 5.3 恢复预算和诊断

保留现有各类恢复的安全边界和次数上限。跨轮次记录原始任务 lineage、恢复原因、已花费次数和实际进展，避免把“每轮 4 次”误报成“整个任务总共 4 次”。

这些计数用于可解释性和确认无进展的保护，不以单纯耗时或总调用量截断仍有真实进展的工作。用户中断、权限等待和已确认循环继续禁止自动父任务重入。

主要接入：`parent-closure-recovery-runtime.js`、`store/parent-closure-recovery-store.js`、`long-task/session-wakeup.js`、`turn-queue-recovery.js`、`turn-queue-dispatch.js`、`turn-orchestrator.js`。

## 6. 子项目 D：循环、活动与任务进展

### 6.1 结构化文本边界

文本重复检测区分代码块/引用/结构化内容与普通叙述。正确关闭代码块后恢复对后续叙述的观察；分片输入不能漏掉跨 chunk 的开闭标记。

不因引用、用户要求重复、合法枚举、计数数据或长代码触发停止。解析状态不确定、输入过大或无法确认边界时保留原路径并记录诊断。

### 6.2 变化不等于进展

将 engine activity 与 task progress 分离：文本/工具活动维持活性；完成有效需求、产物更新、通过新的关联验证属于任务进展。未知工具继续可用，但不能仅凭调用 ID、描述或观察时间变化反复补充“目标进展”额度。

对仅变化编号或措辞的输出，不能粗暴删去数字后直接认定循环。先形成可解释的疑似无进展信号并进行一次有界检查/提示；只有确认无进展且无受保护的前台工作、权限等待时才沿用暂停逻辑。

保留原有精确重复、后台 job 观察稳定化、partial output、bounded abort 和不停止后台进程的行为。不承诺识别所有语义循环。

主要接入：`turn-loop-guard.js`、`task-execution-progress.js`、`opencode-agent-session.js`、`opencode-todo-completion-policy.js` 及现有插件共享 helper。

## 7. 子项目 E：子任务责任和端到端评测

### 7.1 原生执行与平台验收

OpenCode 保留子任务执行权。现有 graph 明确是观测投影，不以新增状态字段假装具备依赖驱动调度。

父任务验收绑定有效需求及子任务交付证据；“子任务返回了一段文字”不能独立证明需求完成。运行中子任务、失败子任务和未经验证的 handoff 必须保留状态，不因父轮次结束自动变成全部通过。

如果后续需要跨任务依赖驱动执行，它是独立子项目，需要真实 worker dispatch 协议、写入冲突边界、取消传播与结果对账后才能启用。本轮不得以“顶级”名义新增第二执行引擎。

### 7.2 评测层次

固定同一组合成任务贯穿以下层次，结果分别记录，不能混用：

1. 机制回归：生产函数、实际 SQLite、受控时钟和网络边界。
2. 客户端集成：真实 Electron 入口/展示，受控模型和合成工作区。
3. 真实模型：完整 Lily 编排入口，指定模型和测试工作区；记录失败，不自动更新基线掩盖回归。
4. 安装包验收：实际 packaged module 加载、资源路径和安装版任务交付。没有安装包或设备时明确未验证。

报告包含源码 SHA、客户端/引擎版本、模型、测试样本、要求数、完成/遗漏/撤销数、错误完成声明、用户额外催促、恢复次数、重复副作用、耗时与可获得的费用信息。成本未知不能填零。

本轮先建立可运行的跨模块场景集和客户端验证入口，不用八项基础模型 smoke test 代表复杂任务成功率。真实模型数据不足时不宣称行业领先或统计学提升。

| A2 | 超过单次审计预算的请求 | 完整输入可取回；覆盖不全保持 unknown |
| A3 | 中文礼貌续接、英文续接 | 有效任务身份和最新要求延续 |
| A4 | 显式新任务/无关问答/旧任务退出 | 不恢复旧任务权限或补做 |

| C3 | 关闭、切账号、删会话、用户中断后迟到 timer | 不再自动启动任务 |

| C5 | 外部操作结果未知 | 不重放；保留检查路径和部分结果 |
| D1 | 关闭代码块后普通文字精确循环 | 能识别；代码内容本身不被误杀 |

| E1 | 多个子任务，一个失败或仍运行 | 父任务不冒充全部验收完成 |
| E2 | packaged 外置 helper 与源码运行 | 都加载正确实现；缺失时保留强默认 |

## 9. 实施顺序及完成定义

按 A → B → C → D → E 分批实施，每批先添加会失败的复现，再进行最小生产修改，最后跑相关历史回归。涉及公共协议时追加版本兼容、跨账号和迟到事件测试。

所有能力变化注册 `CAPABILITY-GATE.md` 和机器可读门禁，运行架构门禁，不提高基线来容纳新增超限。测试失败、跳过、依赖缺失必须分别报告。

本轮完成报告必须逐项给出上表结果，区分实现完成、模拟验证、真实客户端/模型和安装包验证。只通过函数测试不能标记全部产品验收完成。

## 10. 自审结论

- 不新增模型循环、面板或外部部署权限。
- 原始输入不被摘要替代；需求撤销不等于文件删除。
- unknown 不升级成功，也不清空用户成果。
- 恢复按来源和租约对账，不把自动续跑解释成外部操作 exactly-once。
- 保护健康长任务，不用泛化的数字剔除或固定短超时扩大误杀。
- DAG 观测与执行权边界明确；本轮不虚报依赖调度能力。
- 每个修复域有对应生产接入点和失败场景；真实模型/安装包缺少证据时保留未验证状态。
