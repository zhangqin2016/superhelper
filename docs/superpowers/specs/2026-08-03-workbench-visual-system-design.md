# Lily Workbench 视觉系统升级设计

## 目标

在不改变现有业务能力和主要交互入口的前提下，把 Lily Workbench 从“模块各自成型的界面”升级为生产级工作台：信息密度高、扫描路径清晰、状态反馈明确，并具有稳定的 Lily 品牌识别。

## 设计原则

1. **生产力优先**：减少装饰性容器和重复标题，让用户更快找到下一步操作。
2. **统一层级**：页面底、导航、工作区、浮层四种表面使用同一套 token，不允许模块自行发明背景和阴影。
3. **克制品牌色**：中性灰作为主色，Lily 紫只承担选中、主操作、焦点和关键状态，不使用大面积紫色渐变。
4. **状态可读**：选中、悬停、禁用、加载、错误、成功和焦点状态必须有独立的视觉表达，不能只依赖颜色。
5. **稳定布局**：角色库、技能面板、工具卡、输入区使用稳定的网格和尺寸，长内容只能在所属区域滚动。
6. **渐进式改造**：优先调整 token 和共享组件样式，保留现有 DOM 与行为；只有现有结构阻碍可用性时才调整结构。

## 视觉系统

### 色彩

- 页面背景：低对比中性底色。
- 导航层：与页面背景有轻微明度差，不使用厚重卡片。
- 工作区：保持最大阅读对比度，消息内容不包裹在多层卡片中。
- 浮层：使用明确边界和适度阴影，避免玻璃拟态和过度透明。
- 品牌强调：单一 Lily 紫色阶，分别用于 accent、hover、soft、border、focus ring。
- 语义色：成功、警告、错误、信息各自独立，并保证文字对比度。

### 尺寸与排版

- 建立 4px 基础间距阶梯，常用间距集中在 4/8/12/16/24px。
- 正文、辅助文字、标题和代码文字使用统一字号 token，减少同一页面中随意的字号跳跃。
- 标题强调层级，不使用超大标题占用工作区空间。
- 交互控件保持稳定高度；紧凑工作流默认 32/36px，主要操作 40px。
- 圆角以 6/8/10px 为主，只有标签和状态胶囊使用全圆角。

### 表面与边界

- 普通模块使用分隔线、留白和背景层级表达关系，避免卡片套卡片。
- 真正需要聚焦的对象才使用卡片：角色条目、详情面板、工具预览、弹窗。
- 阴影只用于浮层、弹窗和拖拽对象；普通内容不使用大面积阴影。

## 页面范围

### 1. 全局基础层

修改 `src/renderer/styles/base.css` 与 `ui-primitives.css` 的 token 和基础控件：按钮、输入框、选择框、复选框、标签、滚动条、焦点环、禁用态和语义状态。

### 2. 工作台框架

调整顶部栏、左侧工作区导航、右侧辅助面板和聊天主区域的边界、密度和响应式行为。聊天正文保持开放阅读区，减少装饰性边框。

### 3. Composer 输入区

让输入区成为稳定的工作台底部工具栏：主输入区域清晰，角色、技能、附件、权限和自动执行等控制按优先级分组；次要入口不抢占发送操作。

### 4. 角色库与角色切换器

- 快速切换器：紧凑三列网格、内部滚动、底部操作固定可见。
- 角色库：顶部搜索和筛选，左侧分组导航，中间三列条目网格，右侧详情面板。
- 角色、设定、世界书复用同一套条目视觉语言，但通过标签和元信息区分来源与状态。
- 选中态、官方态、本地态、草稿态和冲突态必须可扫描。

### 5. 技能与工具反馈

技能使用横向标签和分组弹层，长列表不改变输入区高度。工具卡、执行状态、失败状态和完成状态采用统一的状态条，不重复堆叠大卡片。

### 6. 设置和空状态

设置页使用分组导航 + 内容区的工作台结构；空状态提供下一步行动，但不写大段功能介绍。错误状态提供原因、恢复动作和必要的诊断信息。

## 非目标

- 不重写业务状态管理、IPC、角色库数据模型或会话协议。
- 不把所有页面改成营销式卡片布局。
- 不引入新的 UI 框架或重量级组件库。
- 不把深浅色主题合并成单一硬编码主题；两套主题继续由 token 驱动。

## 验收标准

1. 角色库在桌面宽度下可同时看到分组、三列条目和详情；窄窗口不发生横向溢出。
2. 长角色列表、技能列表和设置内容只在所属容器滚动，底部主要操作不会被挤出视口。
3. 全局按钮、输入框、浮层和焦点状态视觉一致，且深浅色主题均可读。
4. 常用操作的视觉优先级明确：发送/确认 > 当前上下文控制 > 管理和次要设置。
5. 不新增不可访问的图标按钮、仅靠颜色表达的状态或无法键盘操作的交互。
6. 现有角色库、角色切换、技能选择和会话控制回归测试继续通过。
7. 完成一次桌面与窄窗口视觉验收，并记录剩余问题，而不是只以 CSS 编译通过作为完成标准。

## 实施顺序

1. token 和基础控件。
2. 工作台框架与聊天主区域。
3. Composer 与技能面板。
4. 角色切换器和角色库。
5. 设置、工具卡、空状态与错误状态。
6. 视觉回归、交互回归和可访问性检查。
