# IM 界面改进方案

## 目标与范围

以用户提供的微信桌面截图为视觉基准，修复真实会话的引用态、输入区比例、头像可读性、标题信息和列表选中态。保留现有发送、附件、团队权限与消息同步机制。本次不增加 UI 框架。

## 视觉规则

- 输入面板：左右及底部至少 10px 留白，12px 圆角，完整 1px 低对比边界与轻阴影。编辑区、引用和工具栏共用同一表面。
- 编辑区：默认 76px，随文本增长至 150px；引用出现时不扩大成另一块编辑器。工具栏与文字间隔 12px。
- 引用：左侧细色条，上下两行分别呈现说明与内容；内容最多两行，长单词换行。右侧 28px 关闭按钮，使用 ×，保留本地化辅助名称及键盘焦点。
- 消息：普通消息间隔 18px，连续消息 12px；头像与气泡对齐，群昵称不挤入正文。
- 头像：无照片时使用稳定的中深色背景和白色首字，团队头像不得使用近白背景配白字；群拼图保留。
- 列表：保持整行点击，浅色选中态使用轻绿色背景；文本、预览和时间均可辨认，不增加边框装饰。
- 标题：使用与列表一致的会话资料与姓名解析；详情缺少成员时补充同 ID 的列表资料。副标题只显示团队名称，不呈现 scope ID。

## 实施顺序

1. 修复引用布局与关闭按钮，收紧编辑区默认高度。
2. 修复团队头像与浅色列表选中态。
3. 补齐标题的数据来源，删除副标题内部标识。
4. 使用实际 HTML/CSS 和控制器验证引用显示/关闭、长内容、深浅主题、输入自动增长和窄窗口。

## 验收

## 整体样式收敛

深浅主题统一由 base.css 中的 IM 变量控制：浅色为近白聊天画布、浅灰接收气泡、白色编辑面板；深色降低侧栏与选中行饱和度。列表密度调整为 72px 行高，标题降低到正文大字号，气泡尾角缩小。附件预览收紧为 280px 卡片并限制列表高度至 120px，超出滚动。群详情、表单、消息操作浮层使用同一边界和表面体系；所有控件提供键盘焦点，尊重系统减少动画设置。中文引用与准备状态改为“回复消息”“待发送”，异常状态继续保留明确反馈。

## 检查标准

- 引用按钮无浏览器默认边框；说明、正文、关闭按钮互不遮挡。
- 引用关闭仅清除引用，不删除输入正文。
- 真实页面在深浅主题下均无横向溢出，输入面板处于窗口内。
- 已知联系人姓名与列表一致，副标题不含 team:org_ 等内部值。
- 空白不能发送；多行增长有上限；附件仍留在输入面板内。
- 测试通过不代表安装包更新；交付明确本地验证和发布状态。
