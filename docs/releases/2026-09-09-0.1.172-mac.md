# Mac 0.1.172 release

## Status

Published to origin and the signed manifest; **all three platforms are 0.1.172 in `latest.json`** (darwin-arm64, darwin-x64, win32-x64 — the publisher preserved the Windows entry a concurrent session had published). One item outstanding: the CDN edge cache of the two Mac `latest-mac.yml` feeds is still serving 0.1.169 and must be purged (see "CDN purge").

## Why Mac jumped 0.1.169 → 0.1.172

The public Mac auto-update feed was stuck at 0.1.169: the 0.1.170 and 0.1.171 Mac builds were made but never promoted, and a concurrent session (git identity `qin.zhang`, a different session/machine) kept cutting Windows-only releases and bumping the version each time (170→171→172), so every published `latest.json` was Windows-only and each in-flight Mac build went stale mid-flight. Aligning to the current version (0.1.172) and letting the publisher preserve the existing Windows platform entry ends the race: one manifest, one version, all three platforms.

## Scope

Everything since the last Mac build users actually received (0.1.169):

- Adaptive model request shape learned from the server (max_tokens ↔ max_completion_tokens, temperature, the Responses surface for gpt-6-astra / codex models), generic drop/rename/schema-strip lessons, server-delivered hints, redacted probe telemetry — a new provider quirk is a server setting, not a release.
- API keys / mail passwords no longer written as plain Base64 without an explicit opt-in.
- IM: 1:1 chats named after the other person; nickname → enterprise login → masked phone; the Teams view no longer rebuilds/jumps on every sync; enterprise directory + live presence.
- Task-reliability fixes (recursive recovery, interruption history).
- Engine OpenCode 1.18.21 → 1.18.29.

macOS Apple Silicon + Intel DMGs and auto-update ZIPs only. Server business code was deployed separately (`e3f32553`, live). Signatures ad-hoc (no Apple notarization configured), as with every prior Mac release.
