# Lily Workbench 0.1.166 Release

## Status

**Published.** Version 0.1.166 is formally published for macOS arm64, macOS x64
and Windows
x64. The combined signed manifest preserves both Mac targets and adds Windows;
the Windows stable feed and service release row are live. Mac packages use
source commit **ce12b9a6**. The Windows package includes commit **4aaae0b1**.

## Changes and use

- Task summaries distinguish delivery from verified completion with localized
  labels. A successful final test can count as evidence, including the exact
  supported exit-report wrapper; failed, missing or stale evidence cannot.
- Original requirements and structured output paths inform acceptance. Eligible
  incomplete execution can continue once through the existing durable recovery
  path, preserving permission boundaries and completed work. No new UI action
  is required; ordinary natural-language tasks use this behavior.
- Hidden Electron regression tests disable background timer/renderer throttling.
  This changes the test runner, not product window settings.

## Acceptance boundaries

- Local signature verification is not Apple notarization; no Apple notarization
  was performed. It does not establish Gatekeeper or clean-machine install success.
- No logged-in IM acceptance or fresh real-model acceptance of the new recovery
  loop was performed for these packages. Empty-profile startup is a narrower check.
- Earlier real-client creation and repair tests, the later localized-summary
  check, and current automated tests are separate evidence. The earlier receipt
  and label defects are fixed in source; fresh full-client model acceptance remains
  unverified. See the [historical live record](../superpowers/plans/2026-09-07-task-completion-live-acceptance.md).

## Final publication evidence

- Final full-suite result: **898/898**, exit 0, **453 seconds**.
- Mac source commit **ce12b9a6** and Windows source commit **4aaae0b1** were
  pushed to `feat/opencode-engine`. All 24 changed source files match both Mac
  packaged `app.asar` copies; package version is `0.1.166` in all packages.
  Later release-record changes do not alter binaries.
- All four uploads exited 0; uploaded Qiniu content hashes match locally computed
  hashes. Public HTTP 200, byte length and ETag checks match the local artifacts.
- Local Ed25519 release manifest signature is valid; the public signed manifest
  contains all three targets. Both public Mac architecture feeds match their
  local `latest-mac.yml` files byte for byte, without cache-busting parameters.
- Public Mac release APIs return `0.1.166`, matching installer URL, size and
  SHA-256. Rows: arm64 `rel_t4rtj5zhnk57sz`; x64 `rel_n3tumglmctl71o`.
- Production credential access was initially blocked by approval review. The
  user subsequently authorized publication after the explicit credential-use
  question. The token was consumed in process only, not printed or saved.
- Upload encountered an IPv6 connectivity failure. Release-only local IPv4
  forwarding completed the transfers without changing system network settings.
  Intel ZIP resumed its original upload checkpoint after a connection reset.
  Temporary transfer processes have exited; non-secret helpers were removed
  after final verification. No system proxy configuration was changed.
- The unqualified CDN latest URL returned a stale Windows `0.1.164` manifest;
  a cache-busted request returned Mac `0.1.165`, matching the public release API.
  The temporary proxy initially omitted `fusion.qiniuapi.com`, blocking CDN
  refresh. After allowing that exact observed Qiniu endpoint, refresh returned
  code 200 / success and all three plain public URLs returned the new files.
- The Windows installer, stable auto-update installer and blockmap return HTTP
  200 with the expected byte lengths. The Windows service API reports 0.1.166
  with the same URL, SHA-256 and size as the local installer. Its release row is
  `rel_132cnn4n6qlrs6`.
- The Windows stable feed and CDN refresh were published and independently
  verified. Its first static manifest read was stale; the release script's
  bounded retry succeeded.
- The Windows installer embeds the correct Lily icon and contains OpenCode CLI
  and SDK 1.18.21. It has no Windows Authenticode signature.
- No clean-machine installation or logged-in real-model Windows acceptance was
  performed. Windows packaging guards and focused capability tests passed; the
  final 898/898 full-suite result was recorded on the source/Mac release run.
