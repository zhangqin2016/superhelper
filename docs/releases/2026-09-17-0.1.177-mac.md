## What it carries over the published 0.1.176

Twelve substantive fixes, covering every defect in five acceptance reports plus
the two conversation defects found in the user's own database:

- Deliverable relevance: a turn shows what it delivered, not every file it touched.
- 2026-09-16 capability acceptance, all seven findings.
- 2026-09-17 platform acceptance, all nine.
- X-Test: a conversion never destroys a file it did not produce.
- Stress test: an extraction says what it found, an index says what it covered.
- Runtime packs: one pack per process, and only when that pack is the job.
- A contract only names a helper the running build actually has.
- A lost turn is announced once, not once per restart.
- A reloaded turn shows its answer in the answer slot.
- A prompt the platform sends to itself is marked, not guessed.

## Verified in the built packages, not assumed

- Every module added this session is inside `app.asar`: the internal-prompt
  marker, the runtime-pack runner, job observation, the record timeline, the file
  signature reader, the document content extractor.
- The three changed Python helpers are present in unpacked resources.
- **matplotlib 3.11.2 is installed in both runtimes** — 61 packages in the arm64
  venv, 66 in the x64 interpreter. It reached these packages through
  `requirements-runtime.txt`, not by hand, which is what makes it reproducible.
- pandas 2.3.3 and Pillow 11.3.0 are inside their declared ranges, confirming
  the earlier "manifest drift" reading was pack shadowing rather than drift.
- Both dmgs mounted and verified; no macOS junk files in either.
- The whole build logged zero errors.

The two architectures lay their Python runtime out differently, which is by
design and worth knowing when inspecting them: arm64 keeps packages in
`runtime/venv`, while the cross-built x64 installs them into the base
interpreter and leaves `venv` as a 12 KB shim.
