# 0.1.188 release (mac + windows)

## Scope

macOS ARM64 + Intel and Windows x64, version 0.1.188. Source commit: `dc542b2e`
(release bump) on top of `476a0bb0`.

Includes:
- Auto mode fails over to a working model instead of retrying a dead one
  (model-attributable failure backoff, `avoidModelIds`, bounded side-effect-free
  re-run, never after a manual switch; kill switch `LILY_MODEL_HEALTH_ROUTING=0`).
- A subagent that recovered from a tool failure is no longer marked failed;
  running tools get their own "running/not-ended" label.
- Model picker lists selected models first and badges recently failed ones.

Also shipped: skill catalog refresh (changed packs' patch versions raised and
re-published; see Publication).

## Verification

- All three installers built and packaged: darwin-arm64, darwin-x64, win32-x64.
- Mac DMGs passed the mount verification step (`verify-mac-dmg`), Windows exe was
  signed via signtool.
- Public `latest.json`, the releases API, and the per-platform auto-update feeds
  all resolve to 0.1.188 after CDN refresh (HTTP 200).
- The Windows installer was cross-built on macOS. Its packaged Python runtime
  smoke test (`verify-win-pack.mjs` final step) is by design Windows-only, so it
  was **not** executed on this host — the same path as 0.1.176/0.1.178 Windows
  packages. A real Windows install/launch cycle has not been verified.
- Builds remain ad-hoc signed, not Apple Developer ID signed/notarized; Windows
  signing is the project's standard signtool flow.

## Release-script fix

`publish-local-catalog-server.mjs` read only the first page of the keyset-paged
admin skill/workspace-app lists (50 rows of 68), so a skill whose version already
existed beyond page 1 was missed by the conflict check and rejected by the server
as `SKILL_VERSION_IMMUTABLE`. Fixed in `280626c6` by following `nextCursor` until
the list is exhausted.
