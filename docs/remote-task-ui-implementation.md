# 远程协作桌面交互实施

本计划接续已批准的 `remote-task-collaboration-design.md`。不改变普通 IM 的布局、发送链路和启动性能。

## 视觉与交互约束

- 对话顶部只增加一个按需启用的“协作任务”入口；默认关闭。详情在聊天区域内展开，不再开第四列，不挤压输入框。
- 列表使用白底/深色主题底的任务卡，12px 圆角、16px 内距、12px 卡间距。标题最多两行；一行责任人与状态；卡片只有“查看任务”一个动作。空状态解释用途，不伪造示例任务。
- 详情头部固定返回按钮、任务名与状态。内容区依次是目标、验收标准、交付版本。底部固定当前角色的主操作；危险操作次级显示。
- 字体、边框、颜色、阴影均复用现有主题 token；不用裸原生按钮，不用渐变、大面积高饱和色或仪表盘式统计。最小点击区域 36px，焦点环清楚，支持浅/深色与 RTL。
- 状态由服务端确定：待接受、处理中、待验收、待修改、已验收、已拒绝、已取消。已验收不等于已应用。任何 AI 运行信息都不能把任务改成已验收。
- 接受明确说明只接受协作，不会自动运行或接管另一台电脑。退回必须填写修改意见；验收绑定具体交付版本，并再次明确不会覆盖本地文件。
- 网络请求不阻塞切换会话；旧会话和旧账号的迟到响应不能重新展示。请求中禁用相关提交；未知结果显示“正在确认”并用同一持久命令重试；冲突要求刷新后重审，不能自动修改预期版本重发。
- 离线不显示旧授权正文；失败提供重新加载。关闭详情回到原聊天，保留聊天草稿与消息滚动。

## 实施顺序与验证

1. 桌面任务契约与 journal：`task-view.js`（严格命令与安全投影视图）、`task-commands.js`（加密意图、同键恢复）、SQLite v20 和撤权清理。先写 `test-remote-task-desktop.mjs`，检查超时、重启、重复发送、版本冲突、权限撤销和密文存储，再实现。
2. 签名 client、service、IPC/preload：只暴露任务查询、状态动作与恢复，不暴露任意文件路径或授权信息。新功能关闭时不影响已有 IM。运行既有 IPC/client/scope 测试。
3. renderer 独立模块：任务列表、详情、确认表单、真实服务端状态与失败恢复。使用现有 i18n 三语言、统一 CSS。`test-remote-task-ui.cjs` 在 Electron 验证点击、键盘、窄宽/明暗、迟到响应和未知结果。
4. 验证后记录真实完成范围。创建材料包、工作空间接收和实际安全应用未接通前，生产功能仍默认关闭，不能把此管理界面当作端到端远程协作已完成。

## 异常路径与安全边界

- 草稿冻结后保存包摘要，实际加密所得明文摘要必须一致；未知结果重试不重新选文件、不生成新请求身份。明确首次拒绝可修改表单并用新命令身份重试，已有未知提交不可被后续拒绝推翻。
- 共享原文件被敏感过滤、配置过滤或大小过滤排除时，阻止交付，而不是把它默认为删除。冻结包排除代理配置/指令/连接器配置；导入恶意控制文件包直接拒绝。不自动执行脚本或安装依赖。
- 原始快照只读，工作副本可编辑。已缓存交付在打开时重新核对清单；应用重新检查路径、内容和预览摘要。
- 应用整批冲突拒绝；删除额外确认；已应用的再次预览复用原恢复身份，未完成应用先恢复。启动自动回滚未完成的本地事务，后续用户编辑产生冲突时保留恢复记录。
- 独立本地恢复入口不依赖原远端任务/组织授权，个人账号仍需有效。恢复只撤销本账号曾明确批准的本地写入，不能下载任何已撤权远程材料。
- 范围为用户通过系统文件选择器批准的整个目录，新增文件也需通过具体应用预览；不同机器缺少原绑定时再次选本地目录。无冲突强制覆盖入口。
- 当前列表最多 50 个任务，无历史分页。文件应用单文件上限 64 MiB，超过时应使用独立交付副本。秘密扫描沿用现有覆盖范围，不等同通用 DLP。便携 Node 检查不能抵御恶意本机进程持续竞争替换路径；Windows 掉电持久性未验收。
