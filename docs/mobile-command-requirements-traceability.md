# Lily Mobile Command Pro Requirements Traceability

## 1. Rules And Current Result

This matrix is the canonical requirement-to-contract-to-test-to-release mapping. The 47 definitions imported from [the Task 5 provisional registry](mobile-command-api-completeness-matrix.md#3-normative-provisional-requirement-registry) are copied verbatim; changing or renumbering one requires an explicit supersession record. New IDs fill normative gaps without duplicating those invariants.

`covered` means the specification has a complete planned mapping, not that production code or evidence exists. `blocked` means the mapping depends on named external evidence. `not-applicable` is allowed only when the requirement text itself explains why. Failure class is exactly one of `baseline-fail-open`, `authority-fail-safe`, or `recoverable`.

Current result: **Specification Freeze BLOCKED; Production Release BLOCKED.** See [the readiness checklist](mobile-command-release-readiness-checklist.md).

## 4. Deliberate Non-Applicability

There are no `not-applicable` rows. Every normative behavior has either a planned coverage chain or an explicit blocker; absence of implementation or evidence is never treated as non-applicability.
