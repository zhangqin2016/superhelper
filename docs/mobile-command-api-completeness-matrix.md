# Lily Mobile Command Pro API Completeness Matrix

## 1. Purpose

This matrix is the canonical, machine-validated journey-to-boundary inventory (MC-SPEC-009). Every machine reference is exact: OpenAPI references resolve under `#/components/schemas/`, event references under `https://lilyworkbench.local/schemas/mobile-command-events.schema.json#/$defs/`, and native references under `https://lilyworkbench.local/schemas/mobile-command-native-bridge.schema.json#/$defs/`. State/error semantics link to the canonical [state machines](mobile-command-state-machines.md) and [error catalog](mobile-command-error-recovery-catalog.md).

All mutating HTTP/WS/DataChannel envelopes bind protocol/signature version, exact desktop/mobile/session IDs (pairing events bind `pairingId` instead of a not-yet-created remote session), timestamp, nonce, canonical body hash and device signature. They also require an idempotency key unless the operation is naturally read-only. Projection/read envelopes use explicitly separate bases and cannot inherit mutation authority. Native methods do not create remote envelopes or sign arbitrary payload strings; they sign a canonical digest request defined by the identity contract.

Every explicit `extensions`/native error `details` object is limited to 16 `x-*` keys and bounded primitive, short-array, or one-level-object values. The serialized extensions/details contribution MUST be at most 16 KiB per HTTP body, WS/DC envelope, native request/response, or lifecycle event; receivers reject larger input with `MC-ERR-PROTOCOL-INVALID` before state mutation. Schema field limits remain additional, not substitutes for the total byte budget.

## 3. Ownership And Compatibility

- `file-meta` is not a WebRTC DataChannel. Upload metadata and artifact descriptors travel over authenticated HTTP/WS projection; binary transfer uses authorized HTTP/object storage. DataChannels own only live input/health.
- Artifact download is owned by the file-transfer contract and local artifact adapter, never by native share or the WebRTC runbook.
- Native lifecycle and background transport are owned by the native shell; business state remains in MC-SM-BACKGROUND and MC-SM-UPLOAD.
- Voice capture is a native capability/input adapter; voice transcript/command patch semantics are owned by `mobile-command-voice-input.md` and the agent bridge, not the protocol transport or upload machine.
- The machine schemas implement every canonical HTTP path/event/method named here. Compatibility is additive within a major version; unknown mandatory semantics return `MC-ERR-PROTOCOL-CLIENT-UPGRADE-REQUIRED` and disable remote mutation.
- Routes absent from this matrix and `docs/schemas/mobile-command.openapi.yaml` are non-canonical, not alternate endpoints. Implementers MUST NOT combine route families.
