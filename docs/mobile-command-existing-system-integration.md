## 3. Accepted Repository Terminology And Seams

- `user_id` means `users.id`; an account login is represented by `user_sessions.id`.
- `device_id` means the existing unified `devices.id`. Desktop/mobile role is additive metadata or relation, not a second base device identity.
- `license_id` means `licenses.id`, linked through `license_devices`; it is entitlement context, not account identity.
- A planned `remote_session` is distinct from both local conversation/session identity and `user_sessions` authentication state.
- Server routes enter through `registerRoutes` → `publicRoutes`; desktop commands enter through `TurnOrchestrator.sendUserMessage`.
- Configuration has two current sources with different jobs: bootstrap region/feature policy and signed profile-merged effective config.
- Artifact registry and file staging are local adapters with partial reusable invariants, not remote artifact/upload implementations.

## 4. Confirmed Absences

Repository searches across `server/src` and `server/migrations` found no Mobile Command pairing, remote-session, remote permission/approval, remote audit, TURN credential, upload, or signaling owner. These remain planned domain contracts and migrations. Their names in the implementation map are placement proposals, never verified current interfaces.
