# 移动端控制 - 阶段 1 实施计划

## 核心思路：顶级、越来越聪明

**原则**：
1. **从最简单开始**：先实现一个最小可用版本（MVP）
2. **每步都可验证**：每个阶段都有明确的测试标准
3. **渐进式增强**：在稳定基础上增加功能
4. **失败安全**：新功能失败不影响现有功能

---

## 阶段划分

### 阶段 1：基础配对与消息通道（已完成 demo core）
**目标**：移动端可以发送文本/图片任务到桌面端 Lily 会话，并看到桌面侧回复投影

**交付物**：
- ✅ 数据库迁移（配对表）
- ✅ 服务器配对 API
- ✅ 移动端扫码配对
- ✅ 移动端发送消息到桌面
- ✅ 桌面批准/拒绝/解除配对
- ✅ 手机查看当前受控会话和最近历史
- ✅ 手机查看流式/终态投影
- ✅ 手机一键中断当前运行
- ✅ 手机图片附件进入桌面 turn 的正常文件/视觉处理链路

**验证标准**：
- 移动端可以扫描桌面的 QR 码完成配对
- 移动端发送的消息出现在桌面 Lily 对话中
- 移动端发送图片后，桌面 turn 收到本地化后的附件路径
- 桌面回复/状态可以投影回手机

**当前证据**：见 [Mobile Command Current Demo Status](mobile-command-current-demo-status.md)。该状态表示 Phase 1 web demo 核心可用，不表示生产远控、原生 App、WebRTC/TURN、语音、输入注入或平台矩阵已放行。

---

### 阶段 2：屏幕观察
**目标**：移动端可以查看桌面屏幕

**交付物**：
- 桌面端屏幕捕获服务
- WebRTC 信令服务
- 移动端视频观看器

**验证标准**：
- 移动端可以看到桌面屏幕实时画面

---

### 阶段 3：语音输入
**目标**：移动端可以使用语音输入消息

**交付物**：
- 阿里云 Dashscope ASR 集成
- 移动端语音录制组件
- 语音转文本功能

**验证标准**：
- 移动端可以录音并转换为文本发送

---

### 阶段 4：控制输入
**目标**：移动端可以控制桌面鼠标键盘

**交付物**：
- Windows 输入注入 Helper
- macOS 输入注入 Helper
- 移动端控制界面

**验证标准**：
- 移动端可以移动桌面鼠标
- 移动端可以点击桌面
- 移动端可以输入文本

---

### 阶段 5：文件上传
**目标**：移动端可以上传文件到桌面 Agent

**交付物**：
- 分片上传 API
- 桌面端文件暂存
- Agent 附件集成

**验证标准**：
- 移动端上传的文件可以作为附件发送给 Agent

---

## 当前状态：阶段 1 demo core 已可用

**已完成**：
- 扫码免登录配对、桌面批准、grant-scoped 手机访问
- 手机发任务到桌面会话
- 桌面投影回手机
- 手机中断、会话上下文、最近历史
- 手机图片附件
- 桌面配对管理/解除配对
- Phase 1 自动化 smoke/e2e 覆盖

**下一步**：
1. 真机复验手机图片任务闭环。
2. 补稳定性与观测：断线、桌面离线、重复提交、上传失败、日志 correlation。
3. 再按证据选择 Phase 2 窄切口：语音、屏幕观察或输入注入。
